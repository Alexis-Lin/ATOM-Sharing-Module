⚛ Body Park Atom · 用户分享模块

一套分享模块，覆盖全 App 全场景

排列组合是无穷的，但底层的原子模块是有限的。把分享拆成五个可独立替换的层，代码只维护一套——不同入口只是调用不同的内容原子、模板与载体。

核心抽象 / The Model

五层解耦模型

每一层正交、可独立替换。“存图 / 甩链接 / 扫码”只是第 ④⑤ 层的不同选择，不改变前三层；新增分享场景只需在 ①② 层配置映射。

1
Subject 分享主体我在分享“什么”？
分享源决定主体——从哪里发起就分享什么，用户无需选择：某次训练 · 某周打卡 · 某个动作 · 某个成就 · 高光火柴人 · 官方内容 · 数据导出。
2
Atom 内容原子用哪些“积木”表达？
有限的可复用积木：总结数据 · 动作列表 · 肌肉热力图 · 周期统计 · 火柴人 · 雷达图 · 氛围图……
3
Assembly 组装模板积木怎么“排”？
自由度三级：L1 默认模板（零配置）→ L2 精选模板 2~4 个（横滑切换）→ L3 高阶自由勾选（“自定义”入口）。版式：短图 · 长图 · 卡片。UI 个性化集中在此层。
4
Carrier 载体格式以什么“形式”输出？
图片（直发）· 链接 H5（可交互、自带引流）· 二维码（扫码跳转）。格式决定平台适配尺寸。
5
Path 分发链路怎么“送达”对方？
A→B 送达 · 平台无感适配尺寸（小红书/IG/微信/Story）· 二维码水印 · 公域 H5 跳转下载。
第 ① 层模型 / What Can Be Shared

分享体 = 内容实体 × 用户关系态 ✓ 已决策 07-16

同样是“分享一节课”，其实是两个不同的分享体——课程本身（内容），和“这节课被我练过之后”（实例）。任何官方内容都有机会叠加“用户 × 内容”的关系。

R0 · 内容态

分享课程内容

“这节课很好，推荐给你”

展示课程的模板与内容（官方数据）。动力弱，但链公域 H5，引流价值最高。

R1 · 实例态

分享训练结果

“这节课被我练成了这样”

做了几个动作、卡路里、次数与容量（用户 × 内容数据）。分享动力最强。

实体 ＼ 关系态 R0内容态 · “这个好” R1实例态 · “我练成这样” R2聚合态 · “我在成长” R3衍生态 · “我达成了”

动力梯度：R1 > R3 ≈ R2 > R0（实例最有动力；内容态动力弱、引流价值最高）

高光影像/火柴人动态 = 依附任意 R1 实例的媒体资产，可切出单独分享；数据导出（给 Agent）= 任意格子换 Markdown/CSV 载体输出，属第④层 Pro 变体。
实体轴是开放的：产品内任何“名词”补一行关系态即可成为分享体——E5/E6 正是原子化产品的独有优势，别家拿不出“我和这只哑铃的关系”。

第 ② 层规则 / Atom Polymorphism ★

原子的多态性：一个模板，多种数据绑定

第 ③ 层规则 / Freedom Tiers

主体内自由度三级 ✓ 已决策 07-16

主体内的组合“一定程度自由，但尽量保持简单”——渐进式披露：普通用户零决策，高阶用户有出口。模板 = 预设的原子勾选状态 + 版式，L2 与 L3 底层同构，代码只有一套。

L1 · Default

默认模板

发起分享即出图，替用户做好强意见决策。

决策成本 · 0 步
L2 · Curated

精选模板 2~4 个

每主体预设几个常见原子组合 + 版式，横滑切换。

决策成本 · 1 步
L3 · Custom

高阶自由勾选

菜单式勾选原子，入口收敛在模板列表末位“自定义”。

决策成本 · N 步 · 自愿进入
