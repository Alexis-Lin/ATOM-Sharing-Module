① 分享体系怎么做

原子化：排列组合无穷，底层积木有限

整个体系建立在一个判断上——如果按"页面"做分享，每加一个场景就要重做一次；如果按"积木"做分享，场景是积木的排列组合，一套代码覆盖全部。

"你最后排列组合是无穷的，但是它最下面那一个个原子模块模板是有限的。我们现在就是把所有这些原子模块找出来。" —— 2026-07-16 架构讨论会

① 有限的积木

找出全部内容原子（总结指标、肌肉热力图、动作列表、火柴人…），每个原子只设计一次、只实现一次。

② 无限的组合

模板 = 一组预设的原子组合 + 版式。新增分享场景 = 配一份模板 JSON，不写新代码、不出新设计。

③ 解耦的分层

内容、样式、载体三件事互不影响：换一种输出格式（图/链接/数据），前面两层完全不动。

五层解耦模型（点任意一层看它的选项）

从"分享什么"到"怎么送达"，五层各自独立可替换。这是整个体系的骨架。

什么可以被分享：实体 × 关系态

同样是"分享一节课"其实是两件事——分享课程本身（推荐给你）和分享我练完这节课的结果（我练成这样）。把这个区分推广开，任何内容都能叠加"用户 × 内容"的关系，于是全部可分享内容变成一张矩阵。点格子看详情。

为什么这张矩阵重要：它既是需求清单（每个格子都是一个可做的分享场景），也是扩展规则——产品里新增任何"名词"（新器械类型、新健康数据域），补一行关系态就自动获得完整分享能力。
② 分享路径与分享形式

用户从哪进来，最后以什么形式出去

一次分享 = 路径（从哪发起 → 分享什么 → 用哪个模板）+ 形式（以什么载体输出）。两者正交：同一条路径可以输出成四种形式。

路径规则：分享源决定分享体

用户永远不需要先回答"我要分享什么"——他从哪个页面点的分享，就已经回答了。这省掉了一整步交互。点任意入口看完整链路。

组合自由度：三级渐进

普通用户零决策，高阶用户有出口——模板本质就是"预设好的原子勾选状态"，所以三级底层是同一套东西。

L1 · DEFAULT

默认模板

进入分享页即渲染完毕，直接可发。

决策成本 0 步
L2 · CURATED

精选模板 2~4 个

横滑切换不同风格与信息量。

决策成本 1 步
L3 · CUSTOM

自由勾选原子

入口收在模板列表末位"自定义"。

决策成本 N 步 · 自愿进入

分享形式：四大载体族 🆕

过去讨论集中在图片。但分享的接收方不一定是人（也可能是 AI agent），内容也不只是渲染出来的图（还有摄像头捕获的影像）。同一次训练应该能以五种形式出去。点标签切换载体。

① 图像 Image

面向人 · 社交。零门槛、全平台适配，即时晒图的绝对主力。

② 视频 Video 🆕

面向人 · 社交。平台原生内容、算法权重最高，M 类媒体资产的主要出口。

③ 交互 H5

面向人 · 深度。可下钻、可播放、可更新，自带 App 引流入口。

④ 数据 Data 🆕

面向 AI / Agent。Markdown / CSV / JSON，机器可解析，喂给用户自己的 agent。

⑤ 文档 PDF 🆕

面向人 · 专业。打印级图表报告，给教练、医生或自己存档。

为什么数据类载体值得做：会议里提到的真实用户——"身上戴着一堆设备，所有能吐数据的 App 都用，全喂给自己的 agent 做长寿分析"。这类用户不需要好看的图，需要机器可读的结构化数据。我们做导出，意味着在他的健康数据中枢里我们是数据源而不是数据孤岛；结合大一统健康中心的设想，我们甚至可以成为聚合方。商业上作为 Pro 功能，普通用户无感，专业用户愿意付费。

载体 × 分享体 适配矩阵

规律：越是聚合、长期的数据，数据类与文档类载体价值越高；越是单次、情绪化的内容，图像载体越强。

②.5 报告与洞察 ★ 分享动机的核心

数据回答"我做了什么"，洞察回答"这意味着什么"

课后训练报告是最重要的分享场景族。但真正让用户想分享的不是数据本身——竞品都有数据——而是一个让他惊讶或自豪的判断。这决定了报告该怎么设计。

L1 陈述

"你练了 42 分钟，消耗 386 千卡"
所有 App 都有 · 零分享动机

L2 比较

"比上次多举 12%，超过 88% 同课学员"
多数 App 能做 · 有一定动机

L3 判断 ★

"进步来自组数 +2 而非重量——下次可试 65kg"
我们的差异化 · 这才是 wow

报告的四个粒度

"课后报告"不是一个格子而是一族，粒度越小越偏即时质量反馈，越大越偏成长归因。

粒度格子触发时机内容侧重优先级
动作级E1·R1单动作完成动作质量：火柴人 + AI 点评 + PB（竞品做不了）P1
课程级 ★E2·R1练完一节课全局总结 + 肌群 + 动作列表 + 本次对比P0
计划级E3·R2完成 4/8 周计划阶段成长：起点 vs 终点、能力变化（成长叙事最强）P1
周期级E0·R2周 / 月 / 年结束累计趋势、streak、习惯（年度报告=传播峰值）P1

洞察引擎：六类可枚举的规则 点看例子

关键规则 · 双面报告：分享价值 = 意外性 × 正面性 × 可炫耀性。负面洞察（"你三周没练背"）对用户自己极有价值但绝不会被分享。所以同一份报告有两面——App 内是"教练"（六类全说，含负面与建议），分享出去是"战报"（只带正面，短图 1 条、长图最多 3 条，按分享价值分排序）。与"一张图一个主角"同源：洞察要被选出来，堆满 8 条 = 没有洞察。
冷启动的结构性优势：新用户没有历史，对比/归因/预测类洞察全部失效——但火柴人 AI 点评和具象类比第一次训练就能给出 wow，不依赖任何历史。竞品的首份报告只能说"你练了 30 分钟"。首份报告的体验差距可能是新用户留存的分水岭。
完整讨论见《04-设计-原子与报告 · 第 03 节》
③ 具体的分享样式

积木长什么样，拼起来长什么样

样式分三层看：原子（最小积木，22 个现役 + 7 个健康域预留）→ 模板（原子的预设组合，19+4）→ 成图（模板套上真实数据后的输出）。

1 · 内容原子目录

A~G 类是我们渲染出来的，M 类是摄像头捕获+AI 处理的。每个原子只设计一次，通过"数据绑定"复用到不同场景——比如肌肉热力图，同一套版式可以表达"这个动作练哪"（解剖态）、"我这次练了哪"（强度态）、"我这个月常练哪"（覆盖态）。

2 · 模板总目录

模板 = 预设的原子组合 + 版式 + 默认比例。这份目录同时是设计的工作清单和工程的注册表。

3 · 成图样例（真实比例渲染 · 假数据）

P0 课后报告的四个精选模板，按网格规范 1:1 渲染。宽度统一 360pt，比例差异只影响"能装多少"。

4 · 网格标准（保证拼起来不散架）

尺寸与预算

  • 统一逻辑宽 360pt（@3x 导出 1080px），原子都是全宽横条
  • 比例差异 = 高度预算：3:4 432 · 1:1 312 · 4:5 402 · 9:16 440（含安全区）· 长图不限
  • 范围锁定 1:1 ~ 9:16 + 长图，默认 3:4，不做横图

节奏与规则

  • 边距 24 · 原子间缝 16 · 纵向 8pt 节奏；间距只有六个数（4/8/12/16/24/32）
  • 原子高度三档 S / M / L，每张图最多一个 L——它就是主角
  • 装箱：固定档先占位 → 弹性档吃剩余 → 不足则降档 → 再不足砍位重排（绝不留空值）
  • 出血权只给情绪类原子（氛围图/视频），数据类严格守边距
④ 怎么落地

一套管线，新场景只是配置

工程 · ShareKit 四层管线

  • DataProvider — 每实体一个，统一接口取数；隐私分级在此层强制
  • Composition — 模板注册表（JSON，服务端可下发）；执行装箱与重排
  • Render — 原子组件库；App 原生与公域 H5 共用同一份模板 DSL
  • Carrier — 图像/H5/数据/PDF 四种输出 + 尺寸预设 + 水印 + 埋点

接入新场景 = 写一个 Provider + 配一份模板 JSON，零 UI 开发、零分发开发。

节奏 · 四阶段

  • Phase 1 框架输出（当前）— 原子清单、模板目录、网格标准 ✓
  • Phase 2 核心上线 — 课后报告 + T1~T4 + 图像载体，验证传播效果
  • Phase 3 场景补全 — 单动作、周期打卡、关系卡、排行榜
  • Phase 4 配套完善 — 公域 H5、数据导出（Pro）、PDF 报告、引流闭环

优先级依据：R1 实例态分享动力最强，先做课后报告最快验证。

北极星：流量 · 传播 · 留存。每张分享图底部的二维码、每个 H5 页面的下载入口，都是为了让分享出去的内容能把人带回来。
