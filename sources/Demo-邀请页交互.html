02 · 两版 × 多语言

版本决定做什么，语言决定说什么

这是两个独立的维度，不能合成一个"中文=中国版"。判定版本用 App Store 区 / 账号归属地，不用 IP；语言跟随系统语言，用户可手动改。

版本管的内容也要多语言

"配件券 ¥199" 是版本的东西，但它也得有英文。所以版本配置里的字符串本身带语言键：tier3: {zh:'配件券 ¥199', en:'¥199 accessory credit'}。版本 = 一份带语言键的配置，语言 = 选哪个键。

英文会比中文长 30%~50%

Hero 两行、CTA 一行、三格数据的标签——这三处最先被撑爆。Demo 里切到 English 就能看到 hero 换行位置和标签行高的变化，设计稿要按英文最长那一版定容器高度。

加一门语言 = 加一列

字符串表加一列，版本配置里每条带语言键的字符串加一个键，其他不动。日文、韩文、德文都是这个路径。不新增页面，不新增版本。

03 · 单 CTA

页面上只有一个按钮，选择放在按钮之后

为什么

  • 页面的任务只有一个：让用户按下去。多一个次级按钮就多一次"我该点哪个"。
  • 形式（图 / 链接）和去处（微信 / 相册 / iMessage…）是同一个决定的两半，放在同一张面板里一次选完。
  • 邀请码留在页面上但不做成按钮——它是保底信息，不是动作。

面板结构

  • 两组，按版本决定顺序：CN 图片在上，GLOBAL 链接在上。
  • 每组 = 缩略预览 + 一句说明 + 一排去处。去处按版本配置。
  • "更多"走系统分享面板，兜住所有没列出来的 App。
  • 每个去处都是终点：点完就分享 / 保存 / 复制，面板关掉，toast 确认。

三格数据可点，但不是 CTA

点击 / 购买 / 权益三格和"规则"是导航，不是行动号召——它们把用户带到二级页看东西，不会产生分享。视觉上用卡片而不是按钮，避免和 CTA 争。
