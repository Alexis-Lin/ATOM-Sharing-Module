02 · 简化后的口径

业务只看一个数，用户看三个数

业务侧：通过分享带来的订单数

不追求逐单归因到人也能算清楚。凡是订单带 token（自有商城）或激活时填了码的，都算"分享带来的订单"。两条来源相加就是这个数，不需要联盟链接、不需要安装归因 SDK。

用户侧：点击 · 购买 · 权益

  • 点击：落地页按 token 计数，几乎零成本，但它是用户最先看到变化的数字——动机的第一反馈。
  • 购买：同上面业务口径，按 token 拆到人。
  • 权益：会员天数 + 下一档进度。"再邀 1 位解锁 ×" 这一行是页面上最有推力的一句话。

三个状态，别混

  • 下单 → 数字动、权益标"待到账"
  • 激活 → 权益到账、推送通知
  • 退货 → 权益收回、动态里留痕

用户看到"待到账"会去催朋友激活——把补录压力交给有动机的一方。

03 · 页面要素清单

给设计的任务书

区块内容交互优先级
Hero利益点两句话（好友得什么 / 我得什么）+ 我的邀请码点码复制。码永远可见，是链路断了时的最后一根绳P0
一键分享主按钮 + 两个次按钮（保存图 / 复制链接）拉起分享面板：图片 / 链接 二选一 × 渠道；默认选图片（国内）或链接（海外），由 Profile 决定P0
数据点击 / 购买 / 权益 三格点击进明细页；数字变化时有一次高亮P0
下一档进度"再邀 N 位解锁 ×" + 进度条 + 三档阶梯随购买数实时更新P0
怎么做三步：发给朋友 → 朋友下单 → 你得权益静态，可折叠P0
最近动态脱敏昵称 + 事件 + 来源 + 权益状态新事件置顶高亮P1
邀请明细按人（漏斗态）/ 按来源（图 vs 链接 vs 训练图二维码）只读P1
我的权益总天数 + 已得列表 + 下一档只读P1
规则五问五答只读P0（法务要看）
推送好友下单 / 激活 / 权益到账点击直达邀请页P1
P0 只做邀请页 + 分享面板 + 规则页；明细、权益页、推送、动态流都是 P1。P0 版本里三格数据不可点，进度条保留——它是动机的核心，不能砍。
