01 · 为什么做

现状是"用户想分享但只能截图"

问题

  • 课后分享做得简陋，大量 0 / — / 空值
  • 用户真的想分享 → 只能截图（截图是需求真实存在的证据）
  • 入口零散，没有统一模块

竞品已验证

  • 国内外三家都在用同一组合：总结数据 + 肌肉热力图 + 动作列表
  • 说明这三件套是被验证的高意愿内容
  • 但他们只能做到"陈述数据"

我们的独有

  • AI 姿态识别 → 火柴人、动作点评、自动选材
  • 结构化标签 → 肌肉/器械/模式三个维度
  • 这两件事让我们能做竞品做不了的内容

北极星

流量 · 传播 · 留存
每张分享图底部的二维码、每个 H5 的下载入口，都是为了让分享出去的内容把人带回来。

本期非目标

社区/关注关系 · 完整成就体系 · 计划体系 · 公域 H5 完整站点。这些是依赖项或后续阶段，今天不展开。

02 · 核心思路

原子化：组合无穷，积木有限

"你最后排列组合是无穷的，但是它最下面那一个个原子模块模板是有限的。我们现在就是把所有这些原子模块找出来。" —— 2026-07-16 架构讨论会

按"页面"做分享，每加一个场景就重做一次；按"积木"做分享，场景是积木的排列组合，一套代码覆盖全部。据此把分享拆成五个正交、可独立替换的层。点任意一层看它的选项。

03 · 分享什么

分享体 = 内容实体 × 用户关系态

同样是"分享一节课"其实是两件事：分享课程本身（推荐给你）和分享我练完这节课的结果（我练成这样）。把这个区分推广开，全部可分享内容就是一张矩阵。点格子看详情。

关键规则 ✓ 已决策

分享源决定分享体——用户从哪个页面点分享，就已经回答了"分享什么"，省掉一整步交互。目前梳理出 16 个分享入口。

扩展规则

实体轴是开放的：产品里新增任何"名词"（新器械、新健康数据域），补一行关系态就自动获得完整分享能力。

04 · 真正的 wow ★

数据回答"我做了什么"，洞察回答"这意味着什么"

竞品都能给数据。用户不会为一堆数字点分享，但会为一个让他惊讶或自豪的判断点分享。这是报告设计的重心转移。

L1 陈述

"你练了 42 分钟，消耗 386 千卡"
所有 App 都有 · 零分享动机

L2 比较

"比上次多举 12%，超过 88% 同课学员"
多数 App 能做 · 有一定动机

L3 判断 ★

"进步来自组数 +2 而非重量——下次可试 65kg"
我们的差异化 · 这才是 wow

六类可枚举的洞察 点看例子

关键提案 · 双面报告 待拍板

分享价值 = 意外性 × 正面性 × 可炫耀性。负面洞察（"你三周没练背"）对用户自己极有价值但绝不会被分享。建议：App 内是"教练"（六类全说含负面与建议），分享出去是"战报"（只带正面，短图 1 条、长图最多 3 条）。

05 · 报告不是一个东西

四个粒度，共用一套原子

粒度越小越偏即时质量反馈，越大越偏成长与归因。四个粒度共用同一套原子与模板，差别只在时间跨度和洞察类型。

粒度格子触发时机内容侧重优先级
动作级E1·R1单动作完成动作质量：火柴人 + AI 点评 + PB —— 竞品做不了P1
课程级E2·R1练完一节课全局总结 + 肌群 + 动作列表 + 本次对比P0
计划级E3·R2完成 4/8 周计划阶段成长：起点 vs 终点 —— 成长叙事最强P1
周期级E0·R2周 / 月 / 年结束累计趋势、streak、习惯（年度报告 = 传播峰值）P1

冷启动是结构性优势

新用户没有历史，对比/归因/预测类洞察全部失效——但火柴人 AI 点评和具象类比第一次训练就能给出 wow，不依赖任何历史。竞品的首份报告只能说"你练了 30 分钟"。首份报告的体验差距，可能是新用户留存的分水岭。

06 · 拿什么拼

原子库：29 个现役 + 7 个预留

每个原子只设计一次、只实现一次，通过数据绑定复用到所有场景——比如肌肉热力图，同一套版式表达"这个动作练哪"（解剖态）、"我这次练了哪"（强度态）、"我这月常练哪"（覆盖态）。

两种物质

数据物质（A/B/C 类）：结构化数据 → 我们渲染出来
媒体物质（M 类）：摄像头捕获 → AI 处理
多数分享是两者混合，也存在纯媒体的分享。

差异化护城河

C 类 AI：火柴人 · 动作点评 · 体适能雷达
M 类媒体：AI 自动选材的高光片段 · 漫画风格化
分类实体：肌肉/器械/模式的"平衡与覆盖"叙事

07 · 怎么出去

五大载体族：不只给人看，也给 AI 看

同一份分享体数据，可以用五种形式输出。载体与前三层（分享体/原子/模板）完全解耦——换载体不换内容。点标签切换看形态。

适配规律

越是聚合、长期的数据（周期打卡、健康域），数据导出与 PDF 价值越高；越是单次、情绪化的内容，图像与视频载体越强。M 类媒体资产的主要出口是视频载体。

08 · 长什么样

模板与网格：保证拼起来不散架

模板 = 预设的原子组合 + 版式 + 默认比例，共 27 现役 + 4 预留。这份目录同时是设计的工作清单和工程的注册表——新模板 = 加一条 JSON 记录，不加代码。

尺寸与预算 ✓ 已决策

  • 统一逻辑宽 360pt（@3x 导出 1080px），原子都是全宽横条
  • 比例差异 = 高度预算：3:4 432 · 1:1 312 · 4:5 402 · 9:16 440 · 长图不限
  • 范围锁定 1:1 ~ 9:16 + 长图，默认 3:4，不做横图

节奏与装箱 ✓ 已决策

  • 边距 24 · 原子间缝 16 · 纵向 8pt 节奏；间距只有六个数
  • 原子高度三档 S/M/L，每张图最多一个 L——它就是主角
  • 装箱：固定先占位 → 弹性吃剩余 → 不足降档 → 再不足砍位重排（绝不留空值）
  • 出血权只给情绪类与媒体类原子，数据类严格守边距

给设计的工作方式

按原子出组件规格，不按页面出图。每个原子的变体 = 绑定态 × 表现形式 × 尺寸档，附空状态与深浅色。Figma 库结构直接映射架构：Tokens → Atoms → Templates，设计文件与代码结构同构。先做完 29 个原子组件，27 个模板就是拼装工作。

09 · 怎么落地

ShareKit：新场景 = 配置，不是开发

工程 · 四层管线

  • DataProvider — 每实体一个，统一接口取数；隐私分级在此层强制
  • Composition — 模板注册表（JSON，服务端可下发）；执行装箱与重排
  • Render — 原子组件库；App 原生与公域 H5 共用同一份模板 DSL
  • Carrier — 图像/视频/H5/数据/PDF 五种输出 + 尺寸预设 + 水印 + 埋点

接入新场景 = 写一个 Provider + 配一份模板 JSON，零 UI 开发、零分发开发。

节奏 · 四阶段

  • Phase 1 框架输出（已完成）— 原子清单、模板目录、网格标准 ✓
  • Phase 2 核心上线 — 课后报告 + T1~T4 + 图像载体，验证传播效果
  • Phase 3 场景补全 — 单动作、周期打卡、排行榜、媒体资产与视频载体
  • Phase 4 配套完善 — 公域 H5、数据导出（Pro）、PDF 报告、引流闭环

优先级依据：R1 实例态分享动力最强，先做课后报告最快验证。

M1

ShareKit 内核 + 课后报告 Provider + T1 模板 + 图像载体

M2

模板注册表服务端化 + 自定义勾选 + T2~T4

M3

公域 H5 复用模板 DSL + 视频载体 + 回流归因

M4

新实体接入手册化——写 Provider + 配 JSON 即上线

埋点四件套

分享发起率 · 分享完成率（分渠道）· 模板分布与原子勾选（验证 L2 预设是否命中真实偏好）· 扫码/链接回流与安装归因。上线两周建立基线，再定 Phase 3 顺序。

出血权仅情绪类与媒体类原子可通栏出血；数据类与水印严格守边距（出血的是底不是字）
VI 基线黑白灰 + 亮绿点睛；圆角语义化——圆角/胶囊仅用于按钮，容器 5px、小元件 2px
报告是一族动作级/课程级/计划级/周期级四粒度，共用同一套原子与模板
载体五族图像 · 视频 · H5 交互 · 数据导出（Pro）· PDF 报告；载体与内容完全解耦
隐私三档默认可分享 / 谨慎（只显趋势，主动勾选才外显）/ 禁止（医疗、周期永不进分享）
11 · 今天要拍板

六个问题，按归属分组 待决策

① P0 范围确认 产品

第一批只做课程级课后报告 + 图像载体 + T1~T4？还是把动作级报告（火柴人+AI 点评）也拉进来——它是差异化最强、冷启动最有效的一个。

② 洞察谁来生成 研发

规则引擎（可控、快、免费）vs LLM（自然、多样、有成本与不可控）。建议：规则引擎算结论 + LLM 只润色措辞。

③ 报告页要不要重构 产品+设计

App 内报告页从"数据陈列"改成"一条主洞察 + 支撑数据"？这会影响分享入口位置，也决定分享率的天花板。

④ 漫画影像是否立项 产品

M4 可能是传播力最强的一个（降低出镜门槛 + 平台算法友好 + 自带话题）。要不要作为独立项目排期？先做 2~3 种风格做透。

⑤ 热力图规格 设计

是否含侧面视图（独有可见肌群约 15%，建议 1:1 与长图选配、短图不上）？男女版是否默认跟随用户资料？强度分三档还是五档？

⑥ 依赖项确认 全体

计划体系在不在 roadmap（决定计划级报告能否做）？成就体系何时补全（决定 R3 格子）？器械维度打点是否已有？

我的建议

① 建议把动作级报告拉进 P0——它不依赖历史数据，是新用户第一次就能感受到的差异化；③ 建议做——报告页结构不改，分享率天花板不会变；④ 建议立项但排在 Phase 3，先用 Phase 2 的数据验证传播基线。
