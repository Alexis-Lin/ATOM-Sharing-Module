## 0. 一句话定位

> **一套分享模块，覆盖全 App 全场景。**
> 不同入口在分享时，只是**调用不同的内容原子 + UI 模板 + 载体**，代码与功能只维护一套。

**北极星指标：流量 · 传播 · 留存**（会议共识：分享的本质就是为了这三件事）。所有设计规则都回归到这三个字。

## 1. 核心抽象：五层解耦模型

会议最重要的洞察——"**排列组合是无穷的，但底层原子模块是有限的**"，以及说话人 1 反复强调的"**解耦**"。据此把分享拆成 5 个正交、可独立替换的层：

```
① 分享主体 Subject   —— 我在分享"什么"？（某次训练 / 某个动作 / 某周打卡 / 某个成就…）
        │
② 内容原子 Atom      —— 用哪些"积木"来表达？（总结数据 / 动作列表 / 肌肉热力图 / 火柴人…）
        │
③ 组装模板 Assembly  —— 积木怎么"排"？（默认模板 + 菜单式勾选 + 短图/长图/卡片）
        │
④ 载体格式 Carrier   —— 以什么"形式"输出？（图片 / 链接H5 / 二维码）
        │
⑤ 分发链路 Path      —— 怎么"送达"对方？（A→B、平台适配尺寸、水印/二维码、公域H5跳转）
```

**为什么要这样分层：**
- 层与层之间解耦后，"分享一张图 / 存本地 / 甩个链接 / 扫码"只是**第 ④⑤ 层的不同选择**，不改变前三层。
- 新增一个分享场景（如单动作分享），只需在第 ①② 层配置"主体→原子映射"，无需重写分发逻辑。
- UI 个性化的自由发挥空间集中在第 ③ 层，框架（①②④⑤）保持稳定——正如会议共识："框架别歪了，风格越往后越自由。"

## 2. 第①层 · 分享体模型：什么可以被分享（What）

### 2.1 关键区分：内容 vs 实例 ✅ 已决策 2026-07-16

同样是"分享一节课"，其实是**两个不同的分享体**，目的完全不同：

| | 分享课程内容（内容态） | 分享训练结果（实例态） |
|---|---|---|
| 潜台词 | "这节课很好，推荐给你" | "这节课**被我练过之后**的结果" |
| 展示什么 | 课程的模板与内容（官方数据） | 做了几个动作、卡路里、次数、容量（用户数据） |
| 数据来源 | 官方内容库 | 用户 × 内容 的关系数据 |
| 价值 | 引流（链公域 H5） | 成就感、传播动力最强 |

> 推广开来：**任何官方内容都有机会叠加"用户 × 内容"的关系**。分享体 = 内容实体 × 用户关系态。

### 2.2 两轴模型：内容实体 × 用户关系态

**轴一 · 内容实体（锚定"关于什么"）**
- `E1` 动作（动作库）
- `E2` 课程（workout / oneset / challenge）
- `E3` 计划 / 挑战活动（未来）
- `E4` 教练 / 老师（真人教练、未来 AI 教练）——**人也是内容实体**
- `E5` 肌肉 / 部位（肌肉字典里的肌群，如肱二头肌）
- `E6` 器械（哑铃、杠铃、绳索……）
- `E7` 动作模式 Pattern（上肢推 / 上肢拉 / 蹲 / 髋铰链 / 弓步 / 旋转 / 核心……）——专业训练视角的分类
- `E0` 全局——不锚定具体内容，锚定"我这个人"

> **实体轴是开放的**，且分两类：**对象实体**（E1~E4：动作、课程、计划、教练——具体的"东西/人"）与**分类实体**（E5~E7：肌肉、器械、模式——给动作打标签的维度）。分类实体的 R2 天然是"**平衡/覆盖**"类叙事（推拉比、肌群覆盖热度、器械偏好），这正是原子化组合产品的独有优势——普通课程 App 拿不出"我和肱二头肌的历史"、"我的推拉平衡"。E7 也是 C4 里 PPS 六边形、体适能雷达这些衍生指标的数据地基。

**轴二 · 用户关系态（锚定"我和它的关系"）**
- `R0` **内容态**：官方模板本身，无用户数据——"这个好"
- `R1` **实例态**：我练完**一次**的结果——"我练了，练成这样"
- `R2` **聚合态**：跨时间的累计与趋势——"我坚持、我成长"
- `R3` **衍生态**：系统对我数据的评价（评级/勋章/雷达）——"我达成了"

### 2.3 分享体矩阵（可被分享的全集）

| 实体 ＼ 关系态 | R0 内容态 | R1 实例态（单次） | R2 聚合态（历史） | R3 衍生态（评价） |
|---|---|---|---|---|
| **E1 动作** | 动作卡（类武将卡，链公域动作库） | 单动作训练结果：次数/重量/火柴人/AI 点评 | 该动作历史记录、PB 曲线 | 动作达成徽章、动作评分 |
| **E2 课程** | 课程卡（链公域课程库） | **课后报告**（P0） | 该课 N 刷、成绩趋势 | 课程评级 A/B/S/SS |
| **E3 计划/挑战** | 计划简介卡 | 某次挑战完成 | 计划完成进度 | 挑战达成勋章 |
| **E4 教练/老师** | 教练介绍卡（链公域教练主页） | 跟某教练练的单次记录 | **我 × 教练的关系**：累计跟练 N 节、时长、进步 | 师徒里程碑徽章（如跟练 100 节） |
| **E5 肌肉/部位** | 肌肉科普卡（解剖、相关动作，链肌肉字典） | 本次练到该肌群的强度 | **我 × 肌肉的历史**：练过 N 个动作、N 次训练、总容量 | 部位专精徽章（如"背部大师"） |
| **E6 器械** | 器械介绍卡（用法、适配动作） | 本次用它练的记录 | **我 × 器械的关系**：最爱的哑铃，用过 N 次、练过哪些动作 | 器械里程碑（如"杠铃 10 吨俱乐部"） |
| **E7 动作模式** | 模式科普卡（定义 + 代表动作） | 本次的模式分布（"今天全是推"） | **我的模式平衡**：推拉比、各模式容量占比、欠练模式 | 模式均衡评级、PPS 六边形徽章 |
| **E0 全局（我）** | **个人主页**（未来：头像、照片/视频集、成就墙） | 单次自由训练 | **周期打卡**（周/月/年、streak） | 体适能雷达、勋章墙、PB 集 |

- **高光影像 / 火柴人动态**：不是独立实体，而是依附于任意 `R1` 实例的**媒体资产**，可从实例中切出来单独分享。
- **数据导出（给 Agent）**：不是矩阵中的格子，而是把任意格子的数据换一种载体（Markdown/CSV）输出——属于第④层载体的 Pro 变体。
- 分享动力梯度：`R1 > R3 ≈ R2 > R0`（实例最有动力，内容态动力弱但引流价值最高）。

### 2.4 分享源 → 分享体 绑定（更新版）✅ 已决策 2026-07-16

用户**从哪里发起分享，就分享什么**——分享体由发起位置隐式决定，用户无需先"选择分享什么"。当一个分享源同时命中两个关系态（如动作详情页里既有官方内容又有我的历史），默认取用户数据态，提供轻量切换：

| 分享源（App 内发起位置) | 绑定分享体（矩阵格子） | 默认核心原子 |
|---|---|---|
| (a) 动作库 · 某动作详情页 | E1·R0 动作卡；若有训练历史可切 E1·R2 | 动作卡 + 肌肉热力图(解剖态) |
| (b) 某节课页面 | E2·R0 课程卡；练过可切 E2·R1/R2 | 课程卡 |
| (c) 课后报告 / 某节课训练记录 | E2·R1 课后报告 | 总结数据 + 热力图 + 动作列表 |
| (d) 影像记录 / 高光火柴人动态 | 依附 R1 的媒体资产 | AI 火柴人 + 高光视频 |
| (e) 周期统计页（周/月/年） | E0·R2 周期打卡 | 周期统计 + 历史对比 |
| (f) 成就 / PB / 雷达页 | E0·R3 成就 | 外化成就标识 / 雷达图 |
| (g) 已训练动作 · 历史记录页 | E1·R2 动作历史 | 历史曲线 + PB |
| (h) 教练主页 / 课程页教练区 | E4·R0 教练卡；有跟练史可切 E4·R2 | 教练卡 + 师徒关系数据 |
| (i) 个人主页（未来） | E0·R0 个人主页 | 名片 + 成就墙 + 照片/视频集 |
| (j) 肌肉字典 / 肌群详情页 | E5·R0 肌肉卡；有训练史可切 E5·R2 | 肌肉卡 + 热力图(解剖态) + 历史 |
| (k) 器械详情页 | E6·R0 器械卡；用过可切 E6·R2 | 器械卡 + 使用历史 |
| (l) 模式统计 / 体适能报告视图 | E7·R2 模式平衡 | 模式卡（PPS 六边形/推拉比） |

> 注：火柴人既是"课后报告"里的可选**原子**，也因入口 (d) 可作为媒体资产单独分享——同一积木，两种调用，正是原子化架构的意义。

### 2.5 分享体优先级（矩阵格子视角）

| 分享体（格子） | 说明 | 当前状态 | 分享意愿 | 优先级 |
|---|---|---|---|---|
| **E2·R1 课后报告** | 练完一节课/一次 workout 的结果 | ✅ 已有（较简陋） | 高（动态、每次不同、最像健身房打卡） | **P0** |
| **E0·R2 周期打卡** | 7天 / 本月 / 今年累计的统计概览 | ❌ 缺 | 高 | **P1** |
| **E1·R1/R2 单动作结果与历史** | 某动作本次表现 + 历史记录/PB | ❌ 缺 | 中 | **P1** |
| **E0·R3 成就 / 里程碑** | PB、勋章、评级(A/B/S/SS)、雷达升级 | ❌ 缺（依赖功能补全） | 高（游戏化、炫耀） | **P1 占位** |
| **R1 附属媒体（高光图/视频/火柴人）** | 自拍氛围图、高光动作视频 | 🟡 部分 | 中 | **P2** |
| **E1/E2·R0 官方内容卡** | 动作卡/课程卡，落公域 H5 | ❌ 缺 | 低（非个人产出，动力弱、引流价值高） | **P2** |
| **E4·R0/R2 教练卡与师徒关系** | 教练介绍 + 我跟练 N 节/时长（会议判断"分享老师国内肯定会有"） | ❌ 缺 | 中（关系叙事有情感动力） | **P2** |
| **E5·R2 我 × 肌肉的历史** | 肱二头肌：练过 N 动作、N 次训练、总容量 | ❌ 缺（数据已有，视图缺） | 中（专业感、独有） | **P2** |
| **E6·R2 我 × 器械的关系** | 最爱的哑铃：用过 N 次、练过什么动作 | ❌ 缺（依赖器械维度数据） | 中（趣味叙事、独有） | **P2** |
| **E7·R2 我的模式平衡** | 推拉比、各模式容量占比（动作→模式映射可现场算） | ❌ 缺（数据可算，视图缺） | 中（专业用户高意愿、独有） | **P2** |
| **数据导出（给 AI / Agent）** | 任意格子数据的 Markdown/CSV 载体变体 | ❌ 缺 | 极客高意愿 | **P2 / Pro** |
| **E0·R0 个人主页** | 名片、照片/视频集、成就墙 | ❌ 缺（依赖社区/主页功能） | 中 | **P3 / 未来占位** |
| **E8~E11 健康域（体重/饮食/跑步/睡眠）** | 大一统健康数据中心的分享预留（见 2.6） | ❌ 缺（依赖数据域接入） | 高（大众健康叙事） | **P3 / 预留占位** |

> 会议共识：**R1 实例态分享动力最强**（"我每次练都不一样，能体现成就感"），R0 内容态动力最弱（"平台固定通用的东西，没太多动力"）但引流价值最高。→ 先做课后报告，再补单动作/周期/官方。

### 2.6 健康域扩展预留（大一统健康数据中心视角）🔮

**假设**：未来 BodyPark 是大一统的健康运动数据中心（对标 Apple Health / Google Health Connect）。检验结论：**架构不需要改**——新域接入 = 矩阵加实体行 + 原子目录加 H 系原子，关系态轴（R0~R3）、表现形式、载体、分发链路全部复用。

**域地图**（对照 Apple Health 14 大类 / Health Connect 6 大类）：

| BodyPark 域 | Apple Health | Health Connect | 分享价值 | 隐私默认 |
|---|---|---|---|---|
| **活动/运动**（步数、活动环、跑步/骑行/游泳、路线、跑步动力学） | Activity, Workouts, Mobility | Activity | 高 | ✅ 可分享 |
| **身体测量**（体重、体脂、围度、BMI） | Body Measurements | Body measurements | 高（趋势叙事） | ⚠️ 谨慎：默认只显**趋势/变化量**，绝对值需主动勾选 |
| **营养/饮食**（饮食打卡、宏量、水、咖啡因） | Nutrition | Nutrition | 高 | ✅ 可分享 |
| **睡眠**（时长、结构/阶段、就寝规律） | Sleep | Sleep | 高 | ✅ 可分享 |
| **心肺/生命体征**（静息心率、HRV、VO2max、血压、血氧、呼吸） | Heart, Vitals, Respiratory | Vitals | 中（VO2max/静息 HR 有炫耀价值） | ⚠️ 谨慎 |
| **心理/正念**（正念分钟、情绪） | Mental Wellbeing | (Wellness) | 低~中 | ⚠️ 谨慎 |
| **周期** | Cycle Tracking | Cycle tracking | — | 🚫 默认禁止分享 |
| **医疗类**（用药、症状、听力、血糖等） | Medications, Symptoms, Hearing… | （部分入 Vitals） | — | 🚫 默认禁止分享（数据中心收录，分享端不出现） |

**预留实体（E8~E11，可分享优先域）**：

| 实体 ＼ 关系态 | R0 内容态 | R1 实例态 | R2 聚合态 | R3 衍生态 |
|---|---|---|---|---|
| **E8 身体指标** | 指标科普卡 | 单次称重（弱） | **体重/体脂趋势**、变化量 | 减重里程碑徽章 |
| **E9 饮食/膳食** | 食物/食谱卡 | **一餐打卡**（照片+宏量） | 营养周报、热量收支 | 连续打卡 streak 徽章 |
| **E10 运动会话**（跑步/骑行等非课程运动） | 运动方式科普卡 | **单次跑步**（路线+配速+心率） | 月跑量、配速趋势 | 累计里程徽章（"百公里俱乐部"） |
| **E11 睡眠** | 睡眠科普卡 | **昨晚睡眠**（结构图+时长） | 睡眠周报、规律性 | 早睡/规律徽章 |

**三档隐私分级**（新增的架构规则，健康域必备）：
1. **默认可分享**：训练、活动、营养、睡眠——正常进入分享流程；
2. **谨慎级**：身体绝对值、心肺指标——默认隐藏或只显趋势，需用户主动勾选才外显；
3. **禁止级**：医疗、周期——数据中心收录但**永不进入分享模块**（分享源不出现分享按钮）。

> 协同效应：大一统数据中心让 **Pro 数据导出（给 Agent）** 的叙事更完整——"所有能吐数据的 App"里，我们成为聚合方而非被聚合方。

## 3. 第②层 · 内容原子目录（Atom Catalog）★核心

分享内容的**有限积木**。会议已验证 5 个高意愿通用原子 + 3 个自有差异化原子（见附图《原子模块表》）。这里补全并分组，附**所需数据字段**与**空状态策略**（会议强调："别再出现一堆 0 / — / 空，排版上要把它补满"）。

### 3.0 原子的多态性：一个模板，多种数据绑定 ★设计共性模块的钥匙

同一个原子在不同关系态（R0~R3）下**版式模板复用，只换数据绑定**。这就是"针对共性模块设计模板"的落点——每个原子只设计一次，声明它支持哪几种绑定：

| 原子 | R0 内容态绑定 | R1 实例态绑定 | R2 聚合态绑定 |
|---|---|---|---|

|---|---|---|
| **数字 Number** | 大数字、宫格指标、计数 | A1 A2 |
| **图表 Chart** | 趋势线、对比条、雷达、热力图着色 | A3 C3 B2 |
| **照片 Photo** | 氛围图、自拍、封面 | D1 B3 B4 |
| **视频 Video** | 高光片段、动态回放 | D2 |

### 6.1 自由度三级模型（渐进式披露）✅ 已决策 2026-07-16

主体由分享源定死（见 2.0），主体**内**的组合自由度分三级，"尽量保持简单"：

| 级别 | 面向 | 交互 | 决策成本 |
|---|---|---|---|
| **L1 · 默认模板** | 全部用户 | 发起分享即出图，零配置 | 0 步 |
| **L2 · 精选模板** | 普通用户 | 每主体预设 2~4 个常见模板（不同原子组合+版式），横滑切换 | 1 步 |
| **L3 · 自由组合** | 高阶用户 | 菜单式勾选原子（参考"练就/训鸡"做法，勾选即显示），入口收敛在模板列表末位"自定义" | N 步，自愿进入 |

> 逻辑：L1/L2 是我们替用户做的**强意见**（穷举常见诉求做成模板）；L3 是给高阶用户的**逃生口**，避免霸道又不让菜单复杂度污染主流程。模板本质 = 一组预设的"原子勾选状态 + 版式"，所以 L2 与 L3 底层同构，代码只有一套。

### 6.2 P0 · 课后报告（E2·R1）的 L2 精选模板定义（低保真任务书）

四个模板 = 四种预设的原子组合。T1 即 L1 默认；低保真原型见 `原子-低保真线框总板.html`。

| 模板 | 定位 | 版式 | 原子组合（按序堆叠） |
|---|---|---|---|
| **T1 战报短图**（默认） | 一键出图、最易传播 | 短图（固定比例） | A1 + B2(R1) + G1 |
| **T2 完整长图** | 完整战报、有点有面 | 长图 | A1 + B2(R1) + B1(R1) + A3 + G1 |
| **T3 AI 特色版** | 独有差异化、火柴人 | 短图/长图 | C1 + C2 + A1(精简) + G1 |
| **T4 极简晒图** | 情绪价值、氛围感 | 短图 | D1(全幅) + A1(一个大数字) + A4 + G1 |

规则：G1 在图片载体必带（引流兜底）；A3/A4 无达标数据自动隐藏并重排；D1 无上传用系统配图兜底。
- **三种版式**：
  - **短图（卡片）**：固定长宽比，信息量受高度约束，默认输出、最易传播（"机器摆那拍张图直接发"式的低门槛）。
  - **长图**：想多长多长，承载多原子叠加，适合完整战报。
  - **卡片**：单动作卡/课程卡/成就卡，独立可分享的最小单元。
- **两个增强引擎**（把枯燥数据变有趣）：
  - **具象化引擎**：指标 → 类比（1800kg=举起一辆车、kcal=消耗几个汉堡）。
  - **对比引擎**：本次 → vs 上次 / PB / 本月第几次，体现"App 有历史趋势与洞察能力"。

## 7. 第④层 · 载体与格式（Carrier）

| 载体 | 分发链路 | 核心优势 | 适用场景 |
|---|---|---|---|
| **图片** | 直接发送，无跳转 | 制作简单、全平台适配 | 用户直接查看分享内容 |
| **链接 / H5** | 跳转对应 H5 页面 | 支持交互、自带 App 引流入口 | 需要引导转化的场景 |
| **二维码** | 扫码跳转 H5 页面 | 制作成本低、适配多端 | 私域社群分享 |

**平台无感适配**：默认按目标平台自动补尺寸——小红书 / Instagram / 微信 / Story 各有比例，用户无感但"觉得很好用"。点某平台即套对应尺寸模板。

## 8. 第⑤层 · 分发链路（Path）

- **图片链路**：A 生成图 → 保存/直发 B → 图底带二维码水印（兜底引流）。
- **链接/H5 链路**：A 生成可交互 H5 → B 打开 → 页内"打开/下载 App"入口 → 转化。H5 = 公域页面，**无需下载 App 即可查看**。
- **二维码链路**：A 出码 → B 扫码 → 落 H5（同上）。
- **公域体系**：动作库/课程库做成公域 H5（对标已有 Web 端），分享即链到公域页——获取流量、助传播、促留存的核心底座。

### 13.3 工程（可复用架构模块：ShareKit）

**目标**：全 App 唯一的分享模块，"新场景 = 配置，不是开发"。

**四层管线**（与五层模型对应，①②合并为数据面）：

```
DataProvider 层   每实体一个 Provider，实现统一接口：
                  provide(entityId, relationState) -> AtomData[]
                  · 原子声明 requiredFields + emptyPolicy(hide/fallback/rearrange)
                  · 隐私分级在此层强制：禁止级实体不注册，分享入口不出现
        ↓
Composition 层    模板注册表（JSON/服务端可下发）：
                  Template = { subjectCell, atoms[{code, format, options}], layout }
                  · L1/L2/L3 同构：模板 = 预设勾选态；L3 = 用户改勾选态
                  · 组合器执行"满格"规则：缺数据原子自动隐藏并重排
        ↓
Render 层         原子组件库（App 原生 + H5 同一套模板 DSL）：
                  render(AtomSpec, AtomData, theme) -> View
                  · 短图=固定画板 / 长图=纵向拼接 / 卡片=独立画板
                  · 服务端出图兜底（分享给未装 App 的 H5 场景）
        ↓
Carrier 层        导出与分发：
                  image(尺寸预设+水印+QR注入) / H5(公域路由+deeplink) / QR
                  · 平台尺寸档位表与 Composition 解耦
                  · 埋点在此层统一打
```

**核心数据契约**（伪码）：

```ts
type RelationState = 'R0'|'R1'|'R2'|'R3'
interface ShareSubject { entity: EntityType; entityId: string; state: RelationState }
interface AtomSpec { code: AtomCode; format: FormatType; binding: RelationState }
interface AtomProvider {
  supports: AtomCode[]
  provide(subject: ShareSubject): Promise<AtomData | Empty>  // Empty 携带 emptyPolicy
}
interface Template { id: string; cell: string /*E2R1*/; atoms: AtomSpec[]; layout: 'short'|'long'|'card' }
```

**里程碑**：
- **M1**（对应 Phase 2）：ShareKit 内核 + E2·R1 Provider + T1 模板 + 图片载体。
- **M2**：模板注册表服务端化 + L3 勾选 + T2~T4。
- **M3**（对应 Phase 4）：公域 H5 渲染复用模板 DSL + QR/链接载体 + 回流归因。
- **M4**：新实体接入手册化——写一个 Provider + 配一份模板 JSON 即上线（E5/E6/E7 用此路径验证）。

**接入新分享场景的标准流程**（M4 后）：定义实体格子 → 实现 Provider → 配模板 JSON → 在分享源挂入口。零 UI 开发（复用原子组件），零分发开发（复用载体层）。
