# Body Park Atom · 用户分享模块 结构化设计框架

> 版本 v0.1（低保真框架阶段）· 更新 2026-07-16
> 来源：2026-07-16《健身APP分享功能架构讨论》会议纪要与转录
> 目标：先把**骨架**聊清楚——有限的原子模块 + 解耦的分层结构，暂不陷入字号/颜色/心率等 UI 细节。

---

## 0. 一句话定位

> **一套分享模块，覆盖全 App 全场景。**
> 不同入口在分享时，只是**调用不同的内容原子 + UI 模板 + 载体**，代码与功能只维护一套。

**北极星指标：流量 · 传播 · 留存**（会议共识：分享的本质就是为了这三件事）。所有设计规则都回归到这三个字。

---

## 1. 核心抽象：五层解耦模型

会议最重要的洞察——"**排列组合是无穷的，但底层原子模块是有限的**"，以及说话人 1 反复强调的"**解耦**"。据此把分享拆成 5 个正交、可独立替换的层：

```
① 分享主体 Subject   —— 我在分享"什么"？（某次训练 / 某个动作 / 某周打卡 / 某个成就…）
        │
② 内容原子 Atom      —— 用哪些"积木"来表达？（总结数据 / 动作列表 / 肌肉热力图 / 火柴人…）
        │
③ 组装模板 Assembly  —— 积木怎么"排"？（默认模板 + 菜单式勾选 + 短图/长图/卡片）
        │
④ 载体格式 Carrier   —— 以什么"形式"输出？（图片 / 链接H5 / 二维码）
        │
⑤ 分发链路 Path      —— 怎么"送达"对方？（A→B、平台适配尺寸、水印/二维码、公域H5跳转）
```

**为什么要这样分层：**
- 层与层之间解耦后，"分享一张图 / 存本地 / 甩个链接 / 扫码"只是**第 ④⑤ 层的不同选择**，不改变前三层。
- 新增一个分享场景（如单动作分享），只需在第 ①② 层配置"主体→原子映射"，无需重写分发逻辑。
- UI 个性化的自由发挥空间集中在第 ③ 层，框架（①②④⑤）保持稳定——正如会议共识："框架别歪了，风格越往后越自由。"

## 2. 第①层 · 分享主体清单（What）

用户以"我练过的记录"为视角发起分享。主体是分享的入口与触发点。

| 分享主体 | 说明 | 当前状态 | 分享意愿 | 优先级 |
|---|---|---|---|---|
| **单次训练 / 课后报告** | 练完一节课/一次 workout 的结果 | ✅ 已有（较简陋） | 高（动态、每次不同、最像健身房打卡） | **P0** |
| **周期打卡（周/月/年）** | 7天 / 本月 / 今年累计的统计概览 | ❌ 缺 | 高 | **P1** |
| **单个动作** | 某个动作 + 历史记录 / 动作卡 | ❌ 缺 | 中 | **P1** |
| **成就 / 里程碑** | PB、勋章、评级(A/B/S/SS)、体适能雷达升级 | ❌ 缺（依赖功能补全） | 高（游戏化、炫耀） | **P1 占位** |
| **高光图 / 视频** | 自拍氛围图、高光动作视频 | 🟡 部分 | 中 | **P2** |
| **官方内容（动作库/课程库）** | 平台固定内容，落公域 H5 | ❌ 缺 | 低（非个人产出，动力弱） | **P2** |
| **数据导出（给 AI / Agent）** | Markdown / CSV 结构化数据接口 | ❌ 缺 | 极客高意愿 | **P2 / Pro** |

> 会议共识：**训练结果类分享动力最强**（"我每次练都不一样，能体现成就感"），官方内容动力最弱（"平台固定通用的东西，没太多动力"）。→ 先做训练结果，再补单动作/周期/官方。

## 3. 第②层 · 内容原子目录（Atom Catalog）★核心

分享内容的**有限积木**。会议已验证 5 个高意愿通用原子 + 3 个自有差异化原子（见附图《原子模块表》）。这里补全并分组，附**所需数据字段**与**空状态策略**（会议强调："别再出现一堆 0 / — / 空，排版上要把它补满"）。

### 3.1 数据类原子（Data）
| 原子 | 说明 | 所需数据字段 | 空状态策略 | 差异化 |
|---|---|---|---|---|
| **训练总结指标** | 时长/容量/卡路里/心率/组次 | duration, volume, calories, avgHR/maxHR, reps, sets | 缺项则排版重排为"满格"，不留空宫格 | 通用 |
| **周期统计** | 周/月/年累计训练次数、时长、天数 | period, sessionCount, totalDuration, activeDays, streak | 新用户用"目标进度"占位 | 通用 |
| **历史对比** | 本次 vs 上次 / vs PB / 本月第几次 | vsLast(%), isPB, monthlyRank, trend | 无历史则隐藏该原子（非置空） | 🟡 我们有数据、现场可算 |
| **数据具象化类比** | 1800kg=一辆车、卡路里=几个汉堡 | 由指标现场映射，配类比素材库 | 无达标数据则不触发 | 🟡 增强感知 |

### 3.2 结构类原子（Structure）
| 原子 | 说明 | 所需数据字段 | 空状态策略 | 差异化 |
|---|---|---|---|---|
| **动作列表 / Workout Log** | 力量训练常见的动作明细表 | exercise[], sets, reps, weight, RPE | 无则不纳入组合 | 通用 |
| **肌肉热力图** | 本次/周期练到的肌群着色 | muscleGroup[], intensity, primary/secondary | 至少展示身体轮廓 | 通用（我们有专业肌肉字典） |
| **动作卡** | 单动作的"名片"（类三国杀武将卡/水浒卡），底层链到公域动作库 | exerciseId, name, coverImg, targetMuscle, category | — | 🟡 我们有动作库字段积累 |
| **课程卡** | 官方课程简介卡，链到公域课程库 | courseId, title, cover, duration, level | — | 通用 |

### 3.3 差异化 / AI 类原子（Differentiator）★护城河
| 原子 | 说明 | 所需数据字段 | 空状态策略 | 差异化 |
|---|---|---|---|---|
| **AI 识别火柴人** | 动作姿态识别的火柴人形态 | poseFrames, standardOverlay | 无识别则不展示 | ✅ **独有** |
| **动作分析结论 / Tips** | AI 对动作的点评建议 | analysisText, scorePerDimension | 无则隐藏 | ✅ **独有** |
| **体适能雷达图** | 六大体适能维度雷达，可"每练一次涨一点" | dimensions[6], scoreHistory | 首评估后解锁 | ✅ **独有** |
| **外化成就标识** | 评级(A/B/S/SS)、勋章、进度环、莲花、Push/Pull/Squat 六边形 | rating, badges[], ringProgress[3], pps[3] | 依赖功能补全，先占位 | 🟡 游戏化 |

### 3.4 情绪类原子（Emotion）
| 原子 | 说明 | 所需数据字段 | 空状态策略 | 差异化 |
|---|---|---|---|---|
| **氛围图 / 自拍** | 用户上传或系统配图 | userImg? / systemImgPool | 无上传→系统配图兜底 | 通用 |
| **标题 / 日期 / 文案** | 课名、日期、鼓励文案 | title, date, copy | 日期为关键锚点，必留 | 通用 |
| **高光视频** | 动作高光片段 | videoClip | 无则不纳入 | 🟡 |

### 3.5 引流类原子（Growth）
| 原子 | 说明 | 所需数据字段 | 差异化 |
|---|---|---|---|
| **二维码 / 水印** | 图片底部品牌二维码，扫码跳公域 H5 | brandQR, deeplink | 引流核心 |
| **App 下载入口** | H5 页内"打开/下载 App"按钮 | deeplink, appStoreUrl | 转化核心 |

## 5. 底层数据模型（结构化字段）

分享模块不产生数据，只**消费** App 已有数据。按域整理需上游供给的字段：

- **训练域** `Session`：id, date, type(workout/oneset/challenge), duration, volume, calories, avgHR, maxHR, sets, reps
- **动作域** `Exercise`：id, name, cover, category, targetMuscle(primary/secondary), demoVideo → 公域动作库 URL
- **肌肉域** `MuscleDict`：muscle, muscleGroup（解剖学固定）, region 分区（上肢推/拉/蹲/核心…，有自由度）, front/side view, male/female 版本
- **周期域** `PeriodStats`：range(week/month/year), sessionCount, activeDays, streak, totalVolume/Duration
- **对比域** `Comparison`：vsLast(%), isPB, monthlyRank, trend[]（现场可算）
- **成就域** `Achievement`：rating, badges[], ring[3], pps[3](push/pull/squat), fitnessRadar[6]
- **用户域** `UserContent`：avatar, nickname, uploadedPhoto, AI 火柴人 poseFrames, AI 分析文本
- **具象化素材库** `Analogy`：volume→车辆、calories→食物 的映射与素材图

## 6. 第③层 · 组装与交互（Assembly）

- **默认强意见 + 菜单式自由组合并存**：主体触发即给一套默认组合；用户可在顶部勾选栏增删原子（参考"练就 / 训鸡"做法，勾选即展示、取消即隐藏）。既替用户做了决策，又不霸道穷举。
- **三种版式**：
  - **短图（卡片）**：固定长宽比，信息量受高度约束，默认输出、最易传播（"机器摆那拍张图直接发"式的低门槛）。
  - **长图**：想多长多长，承载多原子叠加，适合完整战报。
  - **卡片**：单动作卡/课程卡/成就卡，独立可分享的最小单元。
- **两个增强引擎**（把枯燥数据变有趣）：
  - **具象化引擎**：指标 → 类比（1800kg=举起一辆车、kcal=消耗几个汉堡）。
  - **对比引擎**：本次 → vs 上次 / PB / 本月第几次，体现"App 有历史趋势与洞察能力"。

## 7. 第④层 · 载体与格式（Carrier）

| 载体 | 分发链路 | 核心优势 | 适用场景 |
|---|---|---|---|
| **图片** | 直接发送，无跳转 | 制作简单、全平台适配 | 用户直接查看分享内容 |
| **链接 / H5** | 跳转对应 H5 页面 | 支持交互、自带 App 引流入口 | 需要引导转化的场景 |
| **二维码** | 扫码跳转 H5 页面 | 制作成本低、适配多端 | 私域社群分享 |

**平台无感适配**：默认按目标平台自动补尺寸——小红书 / Instagram / 微信 / Story 各有比例，用户无感但"觉得很好用"。点某平台即套对应尺寸模板。

---

## 8. 第⑤层 · 分发链路（Path）

- **图片链路**：A 生成图 → 保存/直发 B → 图底带二维码水印（兜底引流）。
- **链接/H5 链路**：A 生成可交互 H5 → B 打开 → 页内"打开/下载 App"入口 → 转化。H5 = 公域页面，**无需下载 App 即可查看**。
- **二维码链路**：A 出码 → B 扫码 → 落 H5（同上）。
- **公域体系**：动作库/课程库做成公域 H5（对标已有 Web 端），分享即链到公域页——获取流量、助传播、促留存的核心底座。

## 9. 差异化护城河（我们独有、竞品拿不出）

1. **AI 识别火柴人** —— 视觉上最独特的东西。
2. **动作分析结论 / AI Tips** —— 我们独有的智能点评。
3. **体适能雷达图** —— 六维评估，"每练一次涨一点"，像玩游戏。
4. **外化成就标识** —— 评级 / 勋章 / 进度环 / 莲花 / Push-Pull-Squat 六边形（对标 Apple 三环、FITBOD 六边形）。
5. **专业肌肉字典 + 男女版 + 正/侧视图** —— 基于解剖学、可 check 的肌群映射。
6. **面向 Agent 的数据导出** —— 2026 的新趋势，极客用户把数据喂给自己的 agent 做长寿分析；作为 **Pro 高阶功能**。

## 11. 待决策 / 开放问题（下周对齐）

1. **自由组合 vs 强意见默认**的边界——完全菜单式，还是默认组合为主、少量可调？
2. **单动作分享的信息颗粒度**——动作详情页很多模块，全部分享 or 部分可选（隐藏 AI/视频）？
3. **肌肉热力图**——是否恢复**侧面视图**？是否做**交互式** + **男女版**？（历史上因布局空间搁置，非技术问题）
4. **外化指标（评级/雷达/环）**需先补齐功能，分享才能自动纳入——先占位。
5. **优先级**：单次训练 > 单动作 / 周期 / 官方课程——下周确认具体上线节奏。
6. **面向 Agent 导出**归入 Pro——格式（Markdown/CSV/JSON）与字段范围待定。
